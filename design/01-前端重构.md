## 1. 目标与非目标

**目标（按优先级）**
1. **一致性**：同一数字/按钮/弹窗/空态全站一种做法（建 primitives + 统一格式化 + 统一 toast/状态）。
2. **手感**：首屏更快、空/错/极端值不塌、写操作有反馈（修 P1-7/P1-10/P1-33/P2-25/P2-38 等前端债）。
3. **好看**：视觉方向由用户选定后再铺开。

**非目标（本轮不做）**
- 不改后端、不碰钱路径、不改 API 契约（88 路由不动）。
- 不换路由方案（hash）、不动 PWA 图标/manifest 体系、不改部署链。
- 不做全站框架迁移：**不引 UI 组件库、不引 Pinia**（先 composables）；可引 `@vue/test-utils` 补组件测试。

## 2. 版本管理（四层）

| 层 | 工具 | 用途 | 回滚粒度 |
|---|---|---|---|
| L1 回合级 | DSH 插件（候选 `@nianchu/dsh-rollback` / `dsh-rewind-plugin`，**待安装实测**） | 每轮对话下「回滚」，撤销本轮工作区文件 + 对话上下文 | 一轮 |
| L2 批次级 | `git worktree` + 分支 `refactor-frontend-v2` | 重构改动与 `main` 隔离；`main` 不动 → 不会触发生产部署 | 整个重构 |
| L3 页面级 | 每完成一页 = 1 commit + 1 tag | 单页出问题可精确回退/对比 | 一页 |
| L4 里程碑级 | `git bundle` 本地备份（每日/每阶段） | 防误删/磁盘故障；跨会话可恢复 | 整库 |

**提交与 tag 规范**
- commit：`feat(refactor): <页面> v<N>`；修复类 `fix(refactor): <页面> <问题>`
- tag：`page-<页面>-v<N>`（如 `page-home-v1`）；里程碑 tag：`m0`、`m1`、`m2`…
- 每次 commit 前必须通过：`npm run build` + `npm test` + `design-check` + 截图；涉及接口再加契约/UI 冒烟。

**每日备份（不 push）**
```bash
git bundle create ../backups/myDca-$(date +%Y%m%d).bundle --all
```
> 备份目录在仓库外；`push` 仍需用户单独授权（push 会触发生产部署）。

**回滚 SOP**
1. 还没 commit → 用 L1 插件回滚到本轮之前（或 `git checkout -- .` + 删新建文件）；
2. 已 commit、单页坏 → `git revert <commit>`（保留历史）或 `git reset --hard <上一个 page tag>`；
3. 整批坏 → `git reset --hard <里程碑 tag>`；
4. 每次回滚在 `docs/04-日志.md` 记一条（回了什么/为什么/验证结果）。

**红线**：任何 `reset --hard` / `clean -fd` 前先 `git bundle` 或打 tag；插件只作用于当前工作区与会话，**不能替代 git 历史**。
