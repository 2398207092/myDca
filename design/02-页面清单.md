# 页面清单与状态矩阵

> 这张表回答一个问题：**哪一页算真的做完了。**
> 只有四个状态全绿 + 门禁 0 违规 + 有截图，才算完成。任一缺失都是"看起来做完了"。

---

## 完成定义

| 项 | 判定方式 |
|---|---|
| 空状态 | 零数据时显示引导，不是白屏或 NaN |
| 加载状态 | 有骨架屏或明确的 loading，不是空白闪烁 |
| 错误状态 | 请求失败有可读提示 + 重试入口，不是静默失败 |
| 极端值 | 大数字（6 位以上）、长文本（超长基金名）、零值、负值，都不溢出、不遮挡 |
| 门禁 | `node scripts/design-check.cjs` 对该页 0 error |
| 截图 | `assets/shots/<页面名>.png`，改完必更新 |

符号：`—` 未评估 ｜ `✅` 已验 ｜ `✗` 缺失

## 处理顺序（按收益排序，不是按编号）

1. **首页** —— 每天第一眼，也是方向样板。方向定了先做这一页。
2. **持仓详情** —— 信息密度最高，最容易暴露 token 不够用。
3. **分红日历** —— 有独立视觉元素（月历），最能体现风格差异。
4. 记一笔 / 新增持仓 —— 表单类，极端值风险高。
5. 其余按实际使用频率。

**不要并行开工多页。** 一页做到底（四状态 + 截图），再做下一页。并行是让各页各弄各的最快方式。

## 记录方式

每做完一页，改两处：

1. 本表对应行的符号
2. 截图存入 `assets/shots/`，命名 `<页面名>.png`

不更新这张表的"完成"，视为没完成。
