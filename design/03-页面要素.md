# 首页要素清单

> **这份文档是原型的验收边界，不是设计稿。**
> 它规定首页必须容纳什么、有哪些状态和交互，但不管长什么样。
> 清单里有而原型没有 = **没做完**。

## 一、页面状态

代码实际是**三态**（`HomePage.vue:145`），不是两态：

```ts
const pageState = ref<'loading' | 'ready' | 'error'>('loading')
```

| 状态 | 触发 | 页面表现（依据 `PageState.vue`） |
|---|---|---|
| `loading` | 初始 | **卡片骨架屏**（`skeleton="card"`），不是文字提示 |
| `error` | 接口失败（`catch` → `pageState = 'error'`） | 错误插画/文案 + **重试按钮**（`@retry="loadData"`） |
| `ready` | 加载成功 | 渲染下面五个区块 |

> 原型必须做 error 态。漏掉它，等于漏掉用户最需要的那一屏。

## 二、区块清单（5 个）

### 区块 1 · 庆祝横幅

| 项 | 内容 |
|---|---|
| 出现条件 | `todayDividend > 0`（今日有分红到账才有） |
| 图标 | `auto_awesome`（填充态），反白，圆角方块底 |
| 文案 | `今日分红 ¥{金额} 到账` |
| 装饰 | 两处模糊色块（左上 brand-light/50、右下 #F5C044/10） |
| 动效 | `celebrate-sheet` 入场 + 2 个 `sparkle-icon` 闪烁（错峰 0.35s） |
| **原型要求** | **必须同时展示"有"和"无"两种状态**，这是首屏第一眼的变化 |

### 区块 2 · 更新日志条

> **常驻**：代码里没有 `v-if`，每天都占一屏位置。已确认保留（用户要看版本变化），
> 但建议后续改成「有新版本才展开、平时收起为一行」。

| 项 | 内容 |
|---|---|
| 图标 | `newsmode` |
| 主行 | 查看更新日志 |
| 副行 | `{版本号} · {标题} · {相对日期}` |
| 右侧 | `chevron_right` |
| 交互 | 点击 → 打开更新日志弹窗 |

### 区块 3 · Hero 分红卡（信息最密）

| 项 | 内容 | 备注 |
|---|---|---|
| 标签 | 预测年度分红 | |
| 主数字 | `¥{格式金额}`，**44–48px** | 原代码 40px，与持仓卡 26px 只差 14px，主次拉不开。目标差 20px 以上 |
| 装饰刻度 | 数字左右各一组三段竖线（3px/2px/2px） | 纯装饰，无信息 |
| 光晕 | `hero-glow` 叠在数字下方 | |
| 徽章 1 | `{N} 天` —— 连续持有/记账天数 | 胶囊，brand-light 底 |

### 区块 4 · 分红覆盖卡（两种形态）

**形态 A · 有支出**（`coverageSummary.totalExpenses > 0`）

| 项 | 内容 |
|---|---|
| 顶部线 | 1px 横向渐变（transparent → brand/30 → transparent） |
| 水印 | 右上角树叶图标，**48px、opacity 0.08**，向右上溢出容器 12px 后被裁切 |
| 标题行 | 钱包图标 + 「分红覆盖」，右侧小字「年度支出 ¥X」 |
| 类目节点 | 胶囊：高 24px、左右内边距 10px、圆角 9999px；内含金额（10px semibold）+ 状态文案（10px），上下两行居中 |
| 节点状态 | **三态**：`已覆盖`（绿）/ `奋斗中`（金）/ `待点亮`（灰），文字与图标同色 |
| CTA · progress | 星标图标 + 「再攒 **¥X** 分红就能点亮 {emoji} {类目名}」 |
| CTA · 其他 | eco 图标 + 一句文案（brand 色） |
| CTA 有无 | `coverageCta` 为空时整条不显示 |
| 交互 | 整卡点击 → 跳分红覆盖页 |

> 这段是整个首页唯一带游戏化的地方：目标不是"还差多少钱"，而是"再攒多少就能点亮一颗树"。
> 设计语言必须能承载这种「未完成 → 点亮」的状态转换，Monarch 的语言里没有对应物。

**形态 B · 无支出**

| 项 | 内容 |
|---|---|
| 图标 | `receipt_long`（灰） |
| 文案 | 「尚未设置生活支出」 |
| 按钮 | 「+ 添加」，brand 实心，圆角 lg，`@click.stop` 跳设置页 |
| 交互 | 按钮阻止冒泡，避免触发整卡跳转 |

### 区块 5 · 持仓列表

| 项 | 内容 |
|---|---|
| 标题行 | 「持仓」+ 右侧 `{N} 支` |
| 空态 | `holdings.length === 0` 时显示引导 |
| 卡片字段 1 | `name`（14px medium）+ `code`（11px tertiary） |
| 卡片字段 2 | **预测分红 22px**（原 26px，为与 Hero 拉开层级而下调）：`> 0` 显示 `¥X/年`（≥10000 转万），否则 `--/年` |
| 卡片字段 3 | 市值 `formatMoney(marketValue)` |
| 卡片字段 4 | 成本 `formatMoney(cost)` |
| 卡片字段 5 | 股息率 `dividendRateText(dividendRate)`，**`type === 'crypto'` 时不显示** |
| 交互 | 整卡点击 → 跳持仓详情 |

> **注意**：这张卡的主数字是**预测分红 /年**，不是市值。
> 说明这个产品的视觉重心在"这支持续给我多少钱"，不在"我现在值多少"。

## 三、交互清单（7 个）

| # | 触发 | 行为 |
|---|---|---|
| 1 | 点「查看指标 / 收起指标」 | 切换展开区显示，图标旋转 |
| 2 | 点「设置指标」 | 跳指标设置页 |

| 5 | 点新增持仓 | 跳新增页 |
| 6 | 点更新日志条 | 打开弹窗 |

## 四、条件分支（14 个）

```
pageState === 'ready'                  页面级
```

## 五、原型验收清单

做完一版原型，逐条打勾。**任一条空着就是没做完。**

- [ ] 5 个区块全部出现，顺序正确
- [ ] 区块 1 能切换「有分红 / 无分红」两种状态

## 六、给"反向校准"留的观察点

做原型过程中，以下三处预计会和 Monarch 的语言打架，发现一条记一条，进 `01-决策.md`：

| # | 冲突点 | 为什么 |
|---|---|---|
| 1 | **预测值需要表达不确定** | Monarch 的主数字是净资产（确定值），我们是预测分红（推算值） |
| 2 | **持仓卡要装 5 层信息** | Monarch 的列表行是"名称 + 余额"两栏，我们是一行里塞名称/代码/分红/市值/成本/股息率 |
| 3 | **涨跌色缺位** | Monarch 是预算类产品，没有行情涨跌，语言里没有这个色 |

## 元素来源审计（2026-10-28）

**背景**：v2 原型里曾出现分红覆盖卡右上角的叶子水印，是从旧代码照搬的，不是设计决策。
经查它同时违反两条：**Monarch 组件清单里没有「图标水印」这类东西**，且它用了 `brand` 绿 `#1A6B56`——
而 **Monarch 的七色里没有绿色**。已删除。

**判据（从这次教训得出）**：只有两类元素允许存在——
（a）Monarch 规范明确的；（b）承载信息、且只使用规范内原子规则自造的。
**纯装饰且规范里没有的，一律删。**

| 元素 | 来源 | 规范有无 | 判定 |
|---|---|---|---|
| 亚麻底 / 白卡 / 圆角 12 / 两档阴影 | Monarch | 有 | ✅ |
| 字重 350–500 / 负字距 | Monarch | 有 | ✅ |
| 橙 `#ff692d` | Monarch | 有 | ✅ |
| 胶囊 9999px（按钮、标签） | Monarch | 有 | ✅ |
| 三态节点胶囊形态 | Monarch Pill | 有 | ✅ 形态合规 |
| 庆祝横幅（浅橙渐变底） | 自造 | 无（规范只有满宽纯橙 Promo Banner） | ⚠️ 自造 |
| 更新日志条（中性灰底） | 自造 | 无 | ⚠️ 自造 |
| Hero 暖渐变底 | 自造 | 无 | ⚠️ 有功能：与下方白卡分层 |
| 12 个月分红柱状图 | 自造 | 无 | ⚠️ 信息图形 |
| 覆盖分段进度条 | 自造 | 无 | ⚠️ 信息图形 |
| 持仓卡三列子行（市值/成本/股息率） | 产品需要 | 无（规范只有两栏） | ⚠️ 超出规范 |
| 底部 tab bar | iOS，非 Monarch | 无 | ⚠️ |
| ~~叶子水印~~ | **旧代码照搬** | 无，且用规范外绿色 | ❌ 已删 |
| ~~顶部渐变线~~ | **旧代码照搬** | 无 | ❌ 已删 |
| 模糊圆 / 光晕 / 闪光动画 / 庆祝 sheet | 旧代码，未采用 | 无 | — 未采用 |

**必须记住的结论**：Monarch 是营销站规范，全站只有 6 个组件
（三种胶囊按钮、Feature Card、Product Screenshot Card、顶部导航、Hero Overlay、Promo Banner）。
**App 需要的组件几乎全得自造。** 所以"按规范来"不能理解为"规范里有才能做"，
而应理解为：**自造组件只许用那 7 个色 + 规范里的圆角/阴影/字重/字距档位。**

**已知的颜色偏离**（不是合规，是刻意偏离，必须留痕）：

| 色 | 值 | 用途 | 为什么必须偏离 |
|---|---|---|---|
| 语义绿 | `#1F7A4D` | 涨、已覆盖 | 七色里没有绿，但产品必须有涨跌 |
| 语义金 | `#D9A227` | 奋斗中 | 七色里没有金，三态需要中间档 |
| 占位灰 | `#8F8C87` | `--` 无数据 | 介于 graphite 与 stone，需要比正文弱但不能看不见 |

## 图标体系（本期已定）

| 项 | 决策 |
|---|---|
| 图标库 | **Lucide**（MIT），`lucide-vue-next` 按需引入 |
| 线宽 | `stroke-width = 1.5`，圆角端点（`stroke-linecap: round`） |
| 颜色 | 一律 `currentColor`，不写死色值 |
| 尺寸 | 常规 20px，导航 22px，语义强调 24px |

**替换策略：不做全站一次性替换。** 现有 212 处 Material Symbols、40+ 种图标，
新页面与新原型直接用 Lucide，老页面在该页重构时顺手替换。

常用映射：

```
eco → Leaf            forest → Trees          receipt_long → Receipt
newsmode → Newspaper  chevron_right → ChevronRight   expand_more → ChevronDown
close → X             arrow_back → ArrowLeft   add → Plus
delete → Trash2       check_circle → CheckCircle2    refresh → RefreshCw
progress_activity → Loader2   workspace_premium → Award
monitor_heart → Activity      account_balance_wallet → Wallet
```
