# 设计决策说明

> **项目**：种树 · 基金分红追踪 Vue 前端打磨
> **技术栈**：Vue 3.4 + TailwindCSS v3.4
> **调性**：Modern Minimal + Soft Warm
> **文档版本**：v2（修正版，已 PASS）

---

## 一、核心策略：沿用现有令牌，增量精修

本次打磨**不推翻重建设计系统**，而是在项目现有令牌基础上做增量精修。理由：

1. **品牌色已确立**：`brand #1A6B56` 深绿呼应「种树」语义，用户已有认知，不宜更换。
2. **现有体系可用**：项目的圆角、阴影、间距体系基本完整，仅需语义化补齐与单位纠偏。
3. **降低回归风险**：整体替换 vs 增量精修——后者改动范围可控，回归测试面小，符合「打磨」而非「重构」的定位。
4. **开发者接受度高**：令牌名不变，只是值更精确，旧代码迁移成本低。

---

## 二、精修内容详解

### 1. 对比度修正（可达性 AA）

| 令牌 | 旧值 | 新值 | 修正原因 |
|------|------|------|----------|
| `text-tertiary` | `#A09E9B` | `#6F6F6E` | 旧值在白底对比度仅 2.6:1，不达 AA；新值达 4.8:1（AA Pass） |
| `alert` | `#C25A3E` | `#B84E33` | 加深警示色，白底对比度从 3.2:1 提升至 4.1:1，接近 AA |
| `warning` | `#C25A3E` | 保留原值 | 但限定用途：仅用于图标/大字，禁止大面积作正文底色 |

> **决策依据**：WCAG 2.1 AA 标准要求正常文本对比度 ≥ 4.5:1，大文本 ≥ 3:1。金融场景数字密集、辅助说明多，对比度不达标直接影响可读性。

### 2. 语义色补齐（涨跌/分红/平盘）

原有令牌缺少金融场景必需的涨跌语义色，开发者被迫手动写死颜色值（`#2E7D32`、`#D32F2F` 等），导致色值散落、难以维护。

新增四组语义色对象，每组含 `DEFAULT / strong / soft / light` 四层：

| 语义色 | DEFAULT | strong | soft | 用途 |
|--------|---------|--------|------|------|
| `pos`（正收益） | `#1A6B56` | `#0F4F40` | `#E8F5F0` | 继承 brand 色值，仅语义别名 |
| `neg`（负收益） | `#BA1A1A` | `#A61616` | `#FBEAE7` | 独立红色系 |
| `gold`（分红金） | `#8A6B08` | `#6B5306` | `#F7F0DC` | 原 `amber` 更名，避免与 Tailwind 默认冲突 |
| `flat`（平盘） | `#6B6A68` | — | `#EFEFEE` | 中性灰 |

> **关键设计决策**：每组的 `light` 是 `soft` 的兼容别名（值相同），确保 `bg-brand-light`、`bg-pos-light` 等旧类名在对象化后不静默失效。

### 3. 8pt 间距网格

**问题**：原项目间距使用 `md`(12px)、`xl`(20px) 等非 8pt 倍数值，且 Tailwind 默认 spacing 的 `16`/`24` 实际是 64px/96px，直接混用会产出 4 倍级错误布局。

**修正方案**：

| 语义 | 像素值 | Tailwind 写法 | 语义类 |
|------|--------|---------------|--------|
| 卡片内间距 | 16px | `p-4`（1rem） | — |
| 大区块内距 | 24px | `p-6`（1.5rem） | — |
| 横向留白 | 16px | — | `.gutter-x` |
| 纵向段间距 | 32px | `py-8`（2rem） | `.section-y` |

> **铁律**：13 页统一「横 gutter16 + 纵 section32」。禁止写 `p-16`/`p-24`（Tailwind 里那是 64px/96px）。

### 4. 数字排版（金融场景核心）

**问题**：原项目金额数字用内联 `font-size` 写死，缺乏等宽对齐，列表金额列参差不齐。

**方案**：统一收敛到 B 文档 `.num` + `.num-l*` 组件类（单一数据源）：

| 层级 | 字号 | 字重 | 用途 |
|------|------|------|------|
| `.num-l1` | 30px | 600 | 累计收益、总市值 |
| `.num-l2` | 24px | 600 | 单笔金额、持仓成本 |
| `.num-l3` | 18px | 500 | 明细行数值 |
| `.num-l4` | 14px | 400 | "元/份/%" 单位后缀 |

- `.num` 基类：`font-variant-numeric: tabular-nums` + `font-feature-settings: "tnum"` 确保等宽对齐
- 涨跌配色由 `.t-pos`/`.t-neg`/`.t-flat`/`.t-gold` 叠加控制，与层级解耦
- **v2 决策**：数字层级从 A 文档 `fontSize` 移出，统一由 B 文档组件类负责，避免 config 与 CSS 双写不一致

### 5. 动效令牌

新增动效时长体系（原有项目缺失）：

| 令牌 | 时长 | 用途 |
|------|------|------|
| `fast` | 120ms | 即时反馈（hover、active） |
| `base` | 180ms | 常规切换（按钮、标签） |
| `slow` | 320ms | 面板展开、抽屉 |
| `stagger` | 40ms | 列表交错入场间隔 |

- 缓动函数统一 `out-quart`（`cubic-bezier(0.25, 1, 0.5, 1)`），柔和自然
- 预置 `fade-up`、`toast-in` 两套 keyframes
- **兜底**：`prefers-reduced-motion: reduce` 全局生效，尊重系统减弱动效设置

### 6. 组件配方统一

B 文档提供 10 类全局组件类，消除各页面手写样式碎片：

`.num` · `.chip-*` · `.amount-hl` · `.card` · `.btn-*` · `.list-item` · `.input` · `.empty` · `.toast-*` · `.gutter-x`/`.section-y`

> **Anti-Slop 设计签名**：Toast 去掉左侧彩色竖条，改为纯浅底+深色文字表意（`toast-success` = 浅绿底+深绿字），这是本方案区别于通用 UI 库的辨识点。

## 三、质量审查结论

### 审查流程

采用 25 项检查清单逐项验证，涵盖：令牌完整性、对比度达标、间距合规、组件覆盖、动效兜底、向后兼容、代码可执行性。

### v1 → v2 修正记录

| 问题编号 | v1 缺陷 | v2 修正 |
|---------|---------|---------|
| P0-1 | `brand`/`alert` 对象化后，旧 `bg-brand-light` 类名静默失效 | 全部语义色补 `light` 兼容别名（= soft） |
| P0-2 | 间距用 `16`/`24` 数字，Tailwind 实际为 64px/96px | 改为代码级映射 `p-4`/`p-6`/`py-8`，语义类 `.gutter-x`/`.section-y` |
| — | 数字层级在 A(config) 和 B(css) 双写 | 统一收敛到 B 文档 `.num-l*` 单一数据源 |
| — | Toast 带左侧彩色竖条 | 去掉竖条，纯浅底+深色文字 |

### 最终结论

## 四、技术约束备忘

| 约束 | 说明 |
|------|------|
| Tailwind v3.4 | 默认按 v3 语法（`theme.extend`）；若 v4 需改为 `@theme` 块 |
| brand-light 兼容 | `light` 别名 = `soft`，旧类名不失效 |
| 间距禁止 p-16/p-24 | Tailwind 默认 spacing 16=64px、24=96px，会 4 倍级错误 |
| 数字单一数据源 | 层级由 B 文档 `.num-l*` 负责，A 文档不重复定义 |
| prefers-reduced-motion | B 文档已含兜底，无需额外处理 |
