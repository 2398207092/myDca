## P0 · 会导致资金错误或账号被接管（5 条）

### P0-3 分红入账仅剩并发窗口 `[复核→挖漏更新]`

- **证据**：原「无 distributed 拦截」已修（`EventService.java:108-110` 有状态拦截）；剩余：读状态→写状态之间无乐观锁/行锁/唯一约束，`DividendAutoDistributeScheduler`（9:30）与手动入账并发可双份 `adjustCash`/复投买入；全部实体无 `@Version`（grep 零命中）、无 SELECT FOR UPDATE（`EventService.java:104-119`）。
- **后果**：并发双请求 → 现金与已收分红翻倍、份额翻倍。
- **修法**：`dividend_events` 加 `(holdingId, type, date)` 唯一约束 + 关键实体 @Version；与 P0-4 同批修。

### P0-4 定投执行无当日防重 `[挖漏·四路独立+库内实锤]`

- **证据**：`DcaPlanService.java:416-526` `executePlan` 只校验 `status==active`，不读 `nextExecutionDate`/`lastExecutedAt`，手动接口可无限重复买入；**库内实锤 2 计划 4 笔同日重复交易**（be27a0b6@2026-07-21、609954c7@2026-08-21，各双笔同额同价，已多投 ¥20/10.33 份）；前端 `DcaExecuteSheet.vue:36-39` 无限重试、`request.ts:137` post 无超时放大重试。
- **后果**：双击、重试、手动+10:00 定时并发 → 重复扣款重复买入（已实际发生）。
- **修法**：入口加当日防重；`dca_executions(plan_id, exec_date)` 唯一约束兜底；前端按钮防重 + post 超时。

### P0-5 删持仓不退本金 `[复核→挖漏更新]`

- **证据**：前半句「删复投交易凭空加现金」已修（2026-10-28 create/delete 对称回退）；剩余：`HoldingService.java:392-396` 删除持仓物理级联销毁全部交易/事件/计划/快照，**不回补现金**、无备份、审计轨迹同步销毁。
- **后果**：误删持仓 → 账面蒸发整笔市值且不可重建。
- **修法**：删除持仓时按初始买入回补现金（或删除前显式确认现金影响）。

### P0-6 取消的分红次日复活 + 事件先删后建无约束 `[复核→挖漏更新·并入原 P2-6]`

- **证据**：`DividendEventSyncService.java:110-113` 对每条记录 delete+recreate，`:101-104` 只保留 `distributed`/`converted`，不保留 `cancelled`；`:167-175` 删除吞异常；`DividendEvent` 无唯一约束。
- **后果**：① 取消的分红次日 6:00 重建为 pending、9:30 自动到账；② 数据源 payDate 漂移 → 已入账事件被删重建再入账（双计）；③ 删除失败时同键双事件。
- **修法**：改 upsert（`(holdingId,type,date)`），cancelled 状态保留。

### P0-7 启动器可种下 CHANGE_ME 匿名 Token（条件性）`[挖漏]`

- **证据**：`DataInitializer.java:46-53` 在「无活跃 Token + 未配 `APP_AUTH_TOKEN`」时自动创建字面量 `CHANGE_ME` 的 `userId=null` 匿名 Token；`AuthInterceptor.java:57-77` 不拒 null userId，可过全部非 admin 接口。原 P0-1 的 GET 接口已删（已核实），此为残留面；当前库匿名 token=0 条（暂不可利用）。
- **后果**：清库/换库漏配环境变量即恢复「匿名持有写钥匙」。
- **修法**：删启动种子逻辑 + 拦截器拒 `userId==null` 的 token + 启动时校验 `APP_AUTH_TOKEN != CHANGE_ME`。

## P1 · 数据失真或静默失效

### P1-1 卖出手续费口径错误（三个问题叠加）`[复核]`

- **证据**：
  - `TransactionService.java:65-67` 与 `:177-181` 都是 `total = qty × price + fee`，对卖出应为 `− fee`。
  - `sellFeeRate`（`Holding.java:106`）全工程零处参与计算，只在表单里存（见 P1-17）。
  - 前端 `TradeAddPage.vue:47-55` 的预览同样是加法。
- **后果**：现金多加 `2 × fee`，IRR / 净投入同向偏差。fee 默认为 0，手动填写时触发。
- **改前必须先定口径**：前端卖出输入的是**总金额**，需明确它是「到账净额」还是「成交总额」——两种理解对应相反实现，不定清就只是把错误换个方向。
- **测试已固化错误**：`TransactionServiceTest.java:104,113-114` 断言 `200×15+10=3010`，改代码必须同步改断言。

### P1-2 月度分红明细金额是实际的 3 倍 `[复核]`

- **证据**：`InsightService.java:126-128` 把该基金当月**登记 + 除息 + 派发三类事件**的 amount 相加；而三条事件金额相同。
- **后果**：日历「月度明细」弹窗数字 ×3。

### P1-3 分红覆盖的「剩余额度」恒为 0 `[复核]`
