## P0 · 会导致资金错误或账号被接管

### P0-1 匿名可获取应用级 Token `[复核]`

- **证据**：`AuthController.java:17-20` 暴露 `GET /api/auth/token`；`AuthService.java:65-83` 返回任意 `userId == null` 的活跃 Token，没有就新建；`AuthInterceptor.java:40` 放行 `/api/auth/**`。
- **后果**：`curl /api/auth/token` 即可拿到可读写全部 `/api/**` 的 Token。若 `APP_AUTH_TOKEN` 未注入，值为字面量 `CHANGE_ME`，等同公开口令。
- **修法**：删除该接口（前端已不调用）；启动时校验 `APP_AUTH_TOKEN != CHANGE_ME`，否则拒绝启动。

### P0-2 匿名可改任意用户密码 `[复核]`

- **证据**：`AuthService.java:283-301` 只接收 `email + password`，不校验旧密码、验证码、调用者身份；`/api/auth/**` 全部放行。
- **后果**：知道邮箱即可在 30 秒内接管账号。
- **修法**：要求 Bearer Token 且 token 的 userId 对应 body.email；或要求旧密码 / `set_password` 验证码。

### P0-3 分红到账无幂等 `[复核]`

- **证据**：`EventService.java:102-167` 无 `status == distributed` 前置判断；每次 `totalDividendReceived += amount`、每次 `adjustCash`、复投分支每次新建交易。
- **后果**：双击、重试、9:30 定时任务与手动触发并发 → 现金与已收分红翻倍、份额翻倍。
- **修法**：首行加状态判断；`dividend_events` 加 `(holdingId, type, date)` 唯一约束。

### P0-4 定投执行无到期校验 `[复核]`

- **证据**：`DcaPlanService.java:388-457` 只校验 `status == active`，不校验 `nextExecutionDate <= today`。
- **后果**：手动接口可无限重复买入；与 20:00 定时器叠加即重复扣款。
- **修法**：入口拒绝未到期执行；增加 `dca_executions(plan_id, exec_date)` 唯一约束。

### P0-5 删复投交易凭空加现金、删持仓不退本金 `[复核]`

- **证据**：创建交易时 `reinvest` 不扣现金（`TransactionService.java:119-123`）；删除时却把 `reinvest` 当买入加回现金（`TransactionService.java:234-238`）。`HoldingService.java:323-337` 删除持仓时不回退初始买入扣的现金。
- **后果**：删一笔复投 → 现金虚增；删持仓 → 本金消失。
- **修法**：删除逻辑按类型区分；长期改为现金流水账本。

### P0-6 取消的分红次日复活并入账 `[复核]`

- **证据**：`DividendEventSyncService.java:111-128` 重建事件时只保留 `distributed` / `converted`，不保留 `cancelled`。
- **后果**：用户取消的错误分红，次日 6:00 同步重建为 pending，9:30 自动到账。
- **修法**：`cancelled` 状态同样保留（或改用 `(holdingId,type,date)` upsert，不 delete+create）。

## P1 · 数据失真或静默失效

### P1-1 卖出手续费口径错误（三个问题叠加）`[复核]`

- **证据**：
  - `TransactionService.java:65-67` 与 `:177-181` 都是 `total = qty × price + fee`，对卖出应为 `− fee`。
  - `sellFeeRate`（`Holding.java:106`）全工程零处参与计算，只在表单里存（见 P1-17）。
  - 前端 `TradeAddPage.vue:47-55` 的预览同样是加法。
- **后果**：现金多加 `2 × fee`，IRR / 净投入同向偏差。fee 默认为 0，手动填写时触发。
- **改前必须先定口径**：前端卖出输入的是**总金额**，需明确它是「到账净额」还是「成交总额」——两种理解对应相反实现，不定清就只是把错误换个方向。
- **测试已固化错误**：`TransactionServiceTest.java:104,113-114` 断言 `200×15+10=3010`，改代码必须同步改断言。

### P1-2 月度分红明细金额是实际的 3 倍 `[复核]`

- **证据**：`InsightService.java:126-128` 把该基金当月**登记 + 除息 + 派发三类事件**的 amount 相加；而三条事件金额相同。
- **后果**：日历「月度明细」弹窗数字 ×3。

### P1-3 分红覆盖的「剩余额度」恒为 0 `[复核]`

- **证据**：`LiveExpenseService.java:106-109` 遇到第一个未覆盖项就把 `accumulated` 设为 `predictedAnnualDividend`。
- **后果**：`remainingDividend = 0`，首页 CTA「还需攒 X」高估为全额。

### P1-4 总资产走势首日现金缺失 `[复核]`

- **证据**：`TotalAssetSeriesService.java:107` `assetMap.getOrDefault(date, lastAsset)`；区间首日无 `asset_snapshots` 时 `lastAsset == null`，跳过现金。
- **后果**：曲线起点塌陷，出现「现金归零」类现象。

### P1-5 现金流水审计必然误报 `[复核]`

- **证据**：`DataAuditor.java:146-153` 用「当前余额」对比「流水净变动」，缺期初现金基数。
- **后果**：每天 WARN，告警疲劳，真正的异常被淹没。

### P1-6 净值只抓 1 年，注释写 5 年 `[复核]`

- **证据**：`FundNavScrapeService.java:44` 注释「最近5年」，`:92` 实际 `oneYearAgo` 过滤。
- **后果**：1 年前的收益对比退化为「变动 0」（`ValueChangeService.java:116-121`）。

### P1-7 日历明细与年度总览永久缓存 `[复核]`

- **证据**：`CalendarPage.vue:237`、`:266` 的 `if (data) return`，切月/切年不重新请求。
- **后果**：看过一次 10 月，再切到 11 月仍显示 10 月明细。

### P1-8 分红表选择器靠最后一层文本兜底 `[复核+外审]`

- **证据**：`DividendTableProvider.java:85-91` 三层选择器实测前两层 0 命中（`jjfl` 已改名、表头是「每10份分红」），仅「权益登记日」生效。抓取失败只 `warn`，不告警。
- **后果**：网站改版即静默停更，界面看不出来。

### P1-9 分红分页空转，每只基金发 10 次请求 `[外审实测]`

- **证据**：`FundDividendScrapeService.java:75-100`；实测 `?page=N` 返回内容完全一致，`hasMore` 永远为真。
- **后果**：9/10 的请求是浪费，提高被风控概率。

### P1-10 未分类持仓不计入总资产，且缺少引导 `[复核]`

- **证据**：`AssetOverviewService.java:52-57` 只汇总 `us_stock` / `gold` / `dividend`。新建持仓页**故意不设**分类字段（分类统一在发现页 / 持仓详情，见 [01-系统.md](01-系统.md) 6.1）。
- **后果**：这是设计取舍，不是 bug；但新建后若不注意横幅，会看到「总资产没变」而以为数据错了。
- **定性**：**设计如此 + 引导不足**。修法不是加分类字段，而是强化未分类提示（或新建成功后直接跳分类引导）。

### P1-11 快照 5 天一次，周/月对比按「不晚于」取值 `[复核]`

- **证据**：`HoldingSnapshotScheduler` cron `0 30 23 1/5 * ?`；`AssetOverviewService.java:68-88` 取 `date <= now-7d` 的最新快照。
- **后果**：周变化实际可能对比 12 天前，误差最多 5 天。

### P1-12 多用户隔离不完整 `[复核+外审]`

- **证据**：`SnapshotListService.java:28-41` `findAll` 无过滤；`CoverageCategoryService.java:56-66` 改类目不校验归属；`UserService.java:93-107` 档案/设置是全局单行。
- **后果**：单用户使用无实害；一旦多账号即越权/串数据。

### P1-13 事务内调用外部 HTTP（≥7 处）`[外审]`

- **证据**：`FundDividendScrapeService.java:64-113`（最坏约 300s 长事务）、`HoldingService.java:136-267`、`EventService.java:102-167`、`ExchangeRateService.java:48-88`、`AuthService.java:89-123`。
- **后果**：连接池只有 5，抓数据期间并发请求会 5s 超时报错。

### P1-14 定投可能按几个月前的净值买入 `[复核]`

- **证据**：`DcaPlanService.java:404-407` 只校验 `nav != null`，不校验 `nav.navDate` 距今多久。
- **后果**：净值抓取断更时（爬虫失效、新基金未入库），定投仍按过期净值折算份额，买入价与真实净值偏离。
- **修法**：`nav.navDate` 超过 N 个交易日（如 5 天）则拒绝执行并告警。

### P1-15 定投预算硬编码 A 股日历 `[复核]`

- **证据**：`DcaPlanService.java:66-67` 固定传 `"china"`，注释写"统一用 china"。
- **后果**：美股定投的月度预算按 A 股交易日数估算，次数偏差（美股的感恩节/独立日不在 `holidays.json` 的 china 集合里）。

### P1-16 成立日接口失败时，兜底日期静默吞掉历史分红 `[子代理复核]`

- **证据**：`DividendTableProvider.java:44` `FALLBACK_MIN_EX_DATE = 2020-01-01`；成立日获取失败时用它过滤。
- **后果**：2020 年前成立的老基金（如华夏成长 2002 年）历史分红被**全部丢弃且无提示**，日历和预测分红都少一截。

### P1-17 `sellFeeRate` 存了不用 `[子代理复核]`

- **证据**：`Holding.java:106` 定义、`HoldingService.java:147/183/671` 读写、两个表单可填，但**零处参与计算**。买入有自动算费（建仓 / 定投 / 前端预览），卖出没有。
- **后果**：用户填了卖出费率以为生效，实际从未被读取。
